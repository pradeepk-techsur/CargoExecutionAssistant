**In `server/src/db/repositories/exceptions.ts`, add:**

1. `export type QueueRow = { id: string; case_reference: string; receipt_position: number; received_at: string; entry_number: string | null; validation_result_id: string; findings_count: number }`
2. `export async function listOpenExceptions(db: Queryable): Promise<QueueRow[]>` — the F7 FR-7.1/FR-7.9 query, exactly:
   ```sql
   SELECT e.id, c.case_reference, e.receipt_position, c.received_at,
          c.entry_number, e.validation_result_id, vr.findings_count
     FROM exceptions e
     JOIN cargo_entries c ON c.id = e.entry_id
     JOIN validation_results vr ON vr.id = e.validation_result_id
    WHERE e.state = 'OPEN'
    ORDER BY e.receipt_position ASC
    LIMIT 501
   ```
   No parameters — the FRD forbids any (FR-7.2/FR-7.3). Convert `receipt_position` via `toReceiptPosition`, `received_at` via `.toISOString()`.
3. `export type ExceptionIdentifierResolution = { status: 'FOUND'; exceptionId: string } | { status: 'ENTRY_PASSED_VALIDATION' } | { status: 'NOT_FOUND' }`
4. `export async function resolveCaseIdentifier(db: Queryable, form: 'UUID' | 'CASE_REF', value: string): Promise<ExceptionIdentifierResolution>`:
   - `form === 'UUID'`: `SELECT id FROM exceptions WHERE id = $1` → `FOUND` with that id, else `NOT_FOUND`.
   - `form === 'CASE_REF'`: one query with a `LEFT JOIN` so a clean (no-exception) entry is distinguishable from no match at all:
     ```sql
     SELECT e.id AS exception_id
       FROM cargo_entries c
       LEFT JOIN exceptions e ON e.entry_id = c.id
      WHERE c.case_reference = $1
     ```
     No row at all → `NOT_FOUND`. A row with `exception_id IS NULL` → `ENTRY_PASSED_VALIDATION` (FR-7.14's "this entry passed validation and has no exception"). A row with a non-null `exception_id` → `FOUND`.
5. `export type ExceptionDetailRow = { id: string; case_reference: string; entry_id: string; state: ExceptionState; receipt_position: number; opened_at: string; closed_at: string | null }`
6. `export async function loadExceptionDetail(db: Queryable, exceptionId: string): Promise<ExceptionDetailRow | null>`:
   ```sql
   SELECT e.id, c.case_reference, e.entry_id, e.state, e.receipt_position, e.opened_at, e.closed_at
     FROM exceptions e JOIN cargo_entries c ON c.id = e.entry_id
    WHERE e.id = $1
   ```
   `opened_at`/`closed_at` come back as `Date | null` — return them as ISO strings (`closed_at` stays `null` when the column is null).

Return an empty map immediately (no statement) when `ids.length === 0`, matching the existing empty-array early-return convention in this file.
