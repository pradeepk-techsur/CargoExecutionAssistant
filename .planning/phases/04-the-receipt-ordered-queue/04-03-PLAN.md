`UUID_RE` matching `entries.ts`'s (case-insensitive, five-group form). Add a

`cargo_entries_case_reference_fmt_chk`).

**`GET /api/exceptions` (FR-7.2, FR-7.9, FR-7.12):**
1. Any query string at all (`Object.keys(req.query).length > 0`) ⇒
   `400 UNSUPPORTED_QUERY_PARAMETER`, naming the first offending key in the
   message (e.g. `` `This endpoint accepts no query parameters (received: ${key}).` ``
   — or use the exact `ERROR_MESSAGES.UNSUPPORTED_QUERY_PARAMETER` default if
   you prefer not to interpolate; either satisfies FR-7.2's "naming the
   offending parameter" as long as the 422/400 detail array names it —
   pattern this after how `entries.ts`'s 422 details name a field).
2. `req.principal === undefined` ⇒ `401 UNAUTHENTICATED` (belt-and-braces,
   matching `entries.ts`'s re-check pattern).
3. Call `listQueue(deps.pool)`; `res.status(200).json(response)`.
4. Set `Cache-Control: no-store` — confirm this already happens globally (it
   does, via `securityHeaders`/the existing §3.2 convention every `/api`
   response gets); do NOT add a second header write here.

**`GET /api/exceptions/:idOrReference` (FR-7.2 — no query params here either,
FR-7.14):**
1. Any query string ⇒ `400 UNSUPPORTED_QUERY_PARAMETER` (same rule as the
   entries detail route).
2. `req.principal === undefined` ⇒ `401 UNAUTHENTICATED`.
3. Resolve the path segment's form: `UUID_RE.test(idOrReference)` →
   `'UUID'`; else `CASE_REF_RE.test(idOrReference)` → `'CASE_REF'`; else
   `400 INVALID_IDENTIFIER`.
4. Call `loadCase(deps.pool, form, idOrReference)`.
   - Result is a `CaseDetailResponse` object ⇒ `res.status(200).json(result)`.
   - Result is the string `'NOT_FOUND'` ⇒ `throw new ApiError(404,
     'EXCEPTION_NOT_FOUND')` (default message "That case could not be found.").
   - Result is the string `'ENTRY_PASSED_VALIDATION'` ⇒ `throw new
     ApiError(404, 'EXCEPTION_NOT_FOUND', 'That entry passed validation, so it
     has no exception.')` — same code, DIFFERENT message, per the FRD's error
     table (both rows use `EXCEPTION_NOT_FOUND`; only the message
     distinguishes them).

Export exactly:
```ts
export function exceptionRoutes(deps: RouteDeps): { get: RequestHandler; getOne: RequestHandler }
```
matching `entries.ts`'s `entryRoutes` factory shape (`RouteDeps` already
exists in `routes/index.ts` — import the type, do not redefine it).

There is NO `post`/`put`/`patch`/`delete` handler in this file — F7 is
GET-only by design (FR-7.10); `csrf.middleware.ts` and `app.ts`'s
`apiNotFoundOr405` already answer any other method on these two paths without
any change (both are data-driven from `API_ROUTE_TABLE`, updated in Task 2).

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| client→API | `req.query` and the `:idOrReference` path segment are untrusted input crossing into these two handlers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-04-05 | Tampering | `routes/exceptions.ts::getOne` — `req.params.idOrReference` | mitigate | Validated against `UUID_RE`/`CASE_REF_RE` BEFORE any service/DB call; a value matching neither is refused `400 INVALID_IDENTIFIER` and never reaches `loadCase`. The value that does reach `loadCase` is always passed to `resolveCaseIdentifier` as a `$1` bind parameter (04-01's mitigation), never concatenated. |
| T-04-06 | Denial of service / Information disclosure | `routes/exceptions.ts::get` (list) — an attacker enumerating query parameters to probe server behaviour | mitigate | FR-7.2's blanket rejection (`Object.keys(req.query).length > 0`) refuses EVERY query string uniformly, with the same 400 regardless of the parameter name's plausibility — there is no parameter whose presence yields different behaviour than another, so there is nothing to enumerate. |
| T-04-07 | Elevation of privilege | Both routes — no per-case ownership check | accept | FR-7.11: one role, no per-user scoping, by product design (same disposition as T-04-02 in 04-02-PLAN.md). Owner: FRD F7 FR-7.11. |
