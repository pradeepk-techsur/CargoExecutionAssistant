```ts
export interface AuditTrailRegionProps {
  readonly exceptionId: string;
  /** Bump (any changing number) to force a refetch — e.g. CaseDetail
   *  increments a caseVersion counter every successful case reload,
   *  including the one DecisionPanel triggers via onDecided (FR-14.12: no

  readonly focusOnMount?: boolean;

```

State: `'loading' | 'error' | { status:'loaded'; data: AuditTrailResponse }`.
Fetch in a `useEffect` keyed on `[exceptionId, refreshToken]` — NOT on an
interval (FR-14.12 forbids polling). A load whose `entries.length === 0`
renders `ErrorState` "The audit trail could not be loaded for this case."
(FR-14.17 — a case always has at least an ENTRY_RECEIVED event; empty is an
error, never an empty-state message). Track whether this is the FIRST
successful load (a ref) to choose the announcement text: "Audit trail. {n}
events." on first load, "Audit trail updated. {n} events." on every
refresh thereafter (both `announceStatus`, polite).

**Rendering, top to bottom, inside `<h2 id="audit-trail" tabIndex={-1}
ref={headingRef}>Audit trail</h2>`:**

1. The sentence "Every state change on this case, oldest first. This record
   cannot be edited or deleted." (FR-14.7's required statement).

   `<p>Record integrity verified — {entry_count} event{s} in sequence.</p>`;
   else → `<div className="usa-alert usa-alert--error" role="alert">Record
   integrity check failed at event {first_divergence_sequence}. Report this
   immediately.</div>` — NO repair action anywhere, ever.
3. An `<ol>` of `<li>` events, ONE per `entries[]` entry IN SERVER ORDER
   (FR-14.1 — never re-ordered, grouped, collapsed, or paginated). Per event,
   DOM order heading → who → when → state change → reason → values
   (FR-14.14):
   - `<h3>{actionLabel(entry)}</h3>` — an `ACTION_META` lookup table with the
     FRD's eight rows EXACTLY (label + a `who(entry)` renderer):
     ```
     ENTRY_RECEIVED                       'Cargo entry received'
     VALIDATION_COMPLETED                 'Validated against required-information rules'
     EXCEPTION_OPENED                     'Exception opened'
     RECOMMENDATION_GENERATED             'AI recommendation generated'
     RECOMMENDATION_UNAVAILABLE           'No AI recommendation available'
     RECOMMENDATION_APPROVED              'Recommendation approved by specialist'
     RECOMMENDATION_EDITED_AND_APPROVED   'Recommendation edited and approved by specialist'
     RECOMMENDATION_REJECTED              'Recommendation rejected by specialist'
     ```
     An UNKNOWN `action_type` (should not happen; defensive) renders the RAW
     string as the heading rather than being skipped (FRD Validation rule).
   - A `<dl>`: **Who** — `entry.actor_type === 'AI'` → `` `AI (${entry.model_id ?? 'not reached'})` `` (NEVER a person's name, FR-14.4, even if some future actor field were non-null); `SPECIALIST` action →
     `` `${entry.actor?.display_name} (specialist)` ``; `SYSTEM` action (the
     two received/opened-during-submission rows) →
     `` `System, during ${entry.actor?.display_name}'s submission` ``.
     **When** — `<time dateTime={entry.occurred_at}>{formatDateTime(entry.occurred_at)}</time>`
     — absolute only, never relative (FR-14.15). **What changed** —
     `` `${humanState(entry.before_state)} → ${humanState(entry.after_state)}` ``
     where `humanState(s)` maps `null→'—'` else replaces `_` with a space and
     title-cases (e.g. `'EXCEPTION_OPENED'→'Exception opened'`,
     `'VALIDATED_CLEAN'→'Validated clean'`).
   - **Reason** (when `entry.reason !== null`): a labelled block "Reason
     given" rendering `entry.reason` verbatim as plain text with line breaks
     preserved (split on `\n` into separate `<p>`s — same pattern as
     `CaseDetail.tsx`'s rationale rendering; NEVER truncated, FR-14.5).
   - **Value change table** (when `entry.values.length > 0`): a real
     `<table>` with `<caption>Values recorded — {actionLabel(entry)}</caption>`,
     `<thead><tr><th scope="col">Field</th><th scope="col">Before</th>
     <th scope="col">After</th><th scope="col">Origin</th></tr></thead>`, one
     `<tr>` per value: Field via a local `humanLabel` map (duplicate
