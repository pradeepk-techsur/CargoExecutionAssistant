```ts
/**
 * Record a decision (F11 POST /api/exceptions/{id}/decision). The
 * Idempotency-Key is generated by the CALLER (DecisionPanel, at the moment
 * the pre-submission summary is rendered — FR-12.14) and passed in here
 * unchanged; this method does not generate or cache it.
 */
async postDecision(
  exceptionId: string,
  body: DecisionCreateRequest,
  idempotencyKey: string,
): Promise<DecisionRecordResponse> {
  return request<DecisionRecordResponse>(
    'POST',
    `/api/exceptions/${encodeURIComponent(exceptionId)}/decision`,
    { body, expectBody: true, headers: { 'idempotency-key': idempotencyKey } },
  );
},
```

plus `chosenType: DecisionType | null`, `values: Record<EntryFieldName,string>`
(edit form only), `reason: string`, `busy: boolean`,
`errors: SummaryItem[]`, `idempotencyKey: string | null` (generated via
`window.crypto.randomUUID()` the MOMENT the stage transitions to `'summary'`
— once per attempt; regenerate if the specialist goes Back and forward again,
per FR-12.14's "generated when the summary was rendered").

**1. Chooser (`stage==='chooser'`):** three `<button type="button"
className="usa-button">` — no `autoFocus`, no pre-selection, DOM order
Approve → Edit and approve/Resolve directly → Reject (FR-12.1). Render
Approve ONLY if `permittedDecisions.includes('APPROVE')`; when absent, render
the sentence "There is no AI recommendation to approve." next to the other
two (FR-12.3). Label the middle button "Edit and approve" when
`recommendation.status === 'AVAILABLE'`, else "Resolve directly" (FRD
presentation-states table). Clicking sets `chosenType` and `stage` to
`'edit'` or `'reject'`.

**2. Edit form (`stage==='edit'`):** ONE `Field` per proposed field
(`recommendation.proposed_values`) when AVAILABLE, pre-populated with
`proposed_value`; else one `Field` per `findings` field name (deduplicated,
"direct resolution"), pre-populated with `entryValues[field] ?? ''`. Each
field's current `ProvenanceBadge` renders BESIDE its input: `origin={isAvailable
? (isChangedFromProposal(field) ? 'HUMAN' : 'AI') : 'HUMAN'}`,
`modified={isAvailable && isChangedFromProposal(field)}` (direct resolution
always shows plain "Specialist-entered" — `modified` omitted). Comparison
mirrors the server's own trim-then-byte-compare EXACTLY (FR-12.6):
```ts
function isChangedFromProposal(field: EntryFieldName, current: string, proposed: string): boolean {
  return current.trim() !== proposed.trim();
}
```
On every `onChange` that flips a field's changed state, call
`announceStatus` with the running count: `` `${n} field${n===1?'':'s'} changed` ``
