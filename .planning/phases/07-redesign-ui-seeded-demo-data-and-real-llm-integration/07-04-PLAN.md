<objective>
Install and wire the Carbon Design System (`@carbon/react`, backed by
`@carbon/styles`, plus `@carbon/icons-react`) into the build pipeline
alongside the existing USWDS pipeline — ADDITIVELY, not as a replacement yet.
Nothing in `web/src/**/*.tsx` changes in this plan. The goal is that after
this plan, `npm run build:css` produces ONE compiled, self-hosted stylesheet
containing BOTH USWDS's classes (still driving every currently-shipped
screen, unchanged) and Carbon's classes (unused so far, ready for the next
five plans to consume one file at a time). This additive approach means the
application never passes through a visually-broken intermediate state during
the multi-wave migration, and every wave's regression gate stays meaningful.

This plan also makes the one Carbon-specific decision the user left open —
which of Carbon's four themes (White / Gray 10 / Gray 90 / Gray 100) this
product uses — and retires 07-03's token seam, which was built on the
premise of an unknown future design and is not the mechanism this concrete,
named target actually uses.

Purpose: unblock every subsequent Carbon-adoption plan with a working,
CSP-compliant, self-hosted Carbon build, with zero risk to the currently
shipped UI.
Output: `@carbon/react` + `@carbon/icons-react` installed and building;
`web/styles/app.scss` compiling Carbon's Sass (White theme) forwarded
alongside USWDS; IBM Plex self-hosted with no CDN reference.
</objective>

**Theme decision (make it now, document it, do not leave it open):**
Choose the **White** theme (Carbon's default light theme). Reasoning to
record in a comment at the top of the new Carbon block in `app.scss`:
CargoExec is a federal case-review application whose screens (queue table,
case detail, audit trail) are read-heavy and reviewed for extended periods —
a light, high-contrast theme reduces eye strain over that kind of sustained
reading task, most closely matches the light, high-contrast convention
federal specialists already expect from USWDS-built government tools (so the
visual transition reads as a redesign, not a mode change), and is Carbon's
own most extensively documented and exercised theme for reliably clearing
WCAG AA contrast pairings out of the box.

Add Carbon's Sass entry to `web/styles/app.scss`, immediately after the
existing `@forward "uswds";` line — do NOT touch or remove anything already
in the file. Before writing the exact `@use`/`@forward` incantation, inspect
the installed package's actual Sass entry points:
```bash
find node_modules/@carbon/styles/scss -maxdepth 1 -type f
find node_modules/@carbon/react/scss -maxdepth 1 -type f 2>/dev/null
```
`@carbon/styles` (the Sass package `@carbon/react` depends on) is the
supported entry point for a project that wants the full compiled component
CSS with a named theme; its canonical configuration shape is a `@use
'@carbon/styles' with ($css--font-face: true, ...)` or a themed `@use
'@carbon/styles/scss/themes' with ($theme: $white);`-style block — verify
the ACTUAL supported API of the exact installed version rather than assuming
a version you have not read, exactly as 07-03 required for the USWDS token
accessor. Do not let a wrong function/module name silently break
`npm run build:css`.

Both `@forward "uswds";` (unchanged) and the new Carbon forward must coexist
in one compiled stylesheet with no class-name collision (USWDS's
`usa-*`/utility classes and Carbon's `cds--*` classes use disjoint prefixes,
so this is expected to be safe — confirm it in the compiled output, not by
assumption).
