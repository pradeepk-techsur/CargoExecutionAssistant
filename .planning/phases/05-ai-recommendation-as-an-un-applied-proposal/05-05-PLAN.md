```tsx
export function ProvenanceBadge(props: { readonly origin: 'AI' | 'HUMAN' }): JSX.Element {
  const isAi = props.origin === 'AI';
  const label = isAi ? 'AI-suggested' : 'Specialist-entered';
  // Two VISUALLY DISTINCT USWDS icons (not the same icon recoloured) plus two
  // distinct USWDS utility token classes for background/text — verify both
  // icon files exist under node_modules/@uswds/uswds/dist/img/usa-icons/
  // before referencing them (e.g. person.svg for HUMAN; a machine/automation-
  // associated icon such as settings.svg or build.svg for AI — pick whichever
  // actually exists in the installed package). The <title> makes the icon's
  // meaning available to assistive tech even though the adjacent text alone
  // already suffices.
  return (
    <span className={`usa-tag ${isAi ? 'bg-primary-darker text-white' : 'bg-base-lighter text-ink'}`}>
      <svg className="usa-icon" aria-hidden="true" focusable="false">
        <title>{label}</title>
        <use xlinkHref={`/assets/img/sprite.svg#${isAi ? 'settings' : 'person'}`} />
      </svg>
      {' '}{label}
    </span>
  );
}
```

that gives sufficient AA contrast for each variant (check
`web/styles/app.scss`'s `$theme-color-*` settings for the palette actually

**Load / error / not-found handling:**
- `status: 'loading'` → `<Loading region="Case" />`.
- A thrown `ApiClientError` with `code === 'EXCEPTION_NOT_FOUND'` → a DEDICATED
  "Case not found" presentation (FR-10.15), NOT the generic `ErrorState`: `<h1>Case
  not found</h1>` + the server's message (which already distinguishes "passed
  validation" from a generic not-found, FR-10.15) + a `<Link to="/queue">Back
  to review queue</Link>`.
- A 401 is already handled globally by `api/client.ts`'s redirect-to-sign-in —
  no special handling needed here (FR-10.15).
- Any other error → the shared `ErrorState` with a `Try again` retry.

**On success — uuid canonicalisation (FR-10.13):** if the URL param does NOT
equal `data.exception.case_reference` (i.e. a uuid or any other string was
used to reach this screen), call `navigate(`/cases/${data.exception.case_reference}`,
{ replace: true })` — `replace`, not `push` (no new history entry), and do
this in a `useEffect` keyed on the loaded data so it happens once per load,
without moving focus or re-rendering the whole screen (the FRD requires "no
full reload... in address bar" — `useNavigate`'s client-side replace satisfies
this; do NOT use `window.location.replace`, which WOULD reload).

   filtering, no severity language), one `<li>` per finding:
